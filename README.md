# THE LAST TRAIN

A complete single-case first-person detective game built with Three.js. Explore a rain-soaked 1932 luxury train, inspect eight physical clues, interview four animated suspects, challenge alibis, connect evidence, and submit a written reconstruction.

## Play locally

Requires Node.js 20.19+ or 22.12+ and a browser with WebGL 2.

```sh
npm ci
npm run dev
```

Open `http://localhost:5173`. To play on another computer on your network, open the Network URL printed by Vite. This lets a Raspberry Pi serve the game while your MacBook renders it. macOS, Windows, and Linux use the same browser build; no platform-specific installer is required.

```sh
npm run build
npm run preview
```

Deploy `dist/` to any static web host. No backend or paid service is required.

## Controls

- **WASD** walk; **Shift** move faster.
- **Drag** to look; **arrow keys** also look; **double-click** locks the mouse.
- **E** examine the highlighted clue or interview a passenger.
- **J / Tab** notebook; **Escape** closes panels or releases the mouse.
- Touch devices offer movement buttons and drag-to-look.

Inspect clues and select **Record evidence** to collect them. During interviews, type questions or select a suggested topic; choose an item under **Present evidence** to confront someone. On the case board, select two collected clues to connect them. The theory page requires a suspect and written motive, method, and timeline. Reasoning and supporting evidence affect the verdict.

Progress, conversation history, notes, evidence connections, and player position save locally. Settings includes JSON save export/import. Different browsers and devices do not share saves automatically.

## Dialogue and optional AI

The default **local narrative engine** is deterministic, topic-aware dialogue with persistent memory, trust, threats, promises, secrets, and evidence-driven contradictions. It accepts typed questions but is not a general-purpose language model.

In **Settings → Optional AI direction**, enter an OpenAI-compatible chat completions endpoint, model, and optional key. The endpoint must permit requests from the game's origin (CORS). HTTP localhost endpoints work when playing locally; a remotely hosted HTTPS game needs an HTTPS endpoint. Only the question and three fact-checked candidate lines are sent. The model selects a delivery, and invalid responses/timeouts fall back to local dialogue. Keys stay in memory and are never included in exported saves. Use a local service or a restricted development key; a production service should use a server-side credential proxy.

This deliberately limits remote AI to performance selection rather than arbitrary generated facts. Canonical truth cannot be rewritten by dialogue.

## Architecture

- `src/systems/case.js`: frozen canonical case, evidence, timeline, player discoveries, save validation, board connections, and accusation evaluation.
- `src/systems/dialogue.js`: NPC memory, trust, evidence gating, contradiction detection, local dialogue, and optional AI service.
- `src/world/environment.js`: generated train, furniture, interactive evidence, materials, collision bounds, rain, scenery, and lighting.
- `src/world/characters.js`: articulated characters, procedural faces and clothing, emotion animations.
- `src/systems/audio.js`: synthesized train, rain, music, footsteps, and dramatic cues.
- `src/main.js`: rendering, player controller, interaction, cinematic states, inspection viewer, notebook/UI, and integration.

All 3D assets and audio are generated by code. Fonts are bundled locally under their included SIL Open Font Licenses, with system fallbacks. The visual treatment is procedural and stylized; there are no scanned human characters, voice performances, or downloaded cinematic assets. The station/exterior is a cinematic backdrop; the five connected train interiors are the walkable investigation space.

## Performance

Use **Settings → Low** on weaker graphics hardware. Geometry is shared and static train surfaces are batched by material. Pixel ratio is capped; there are no real-time shadow maps or high-resolution downloaded textures. Best results come from hardware-accelerated browsers. Serving from a Raspberry Pi does not require rendering on the Pi.

## Verification

```sh
npm test
npm run build
npx playwright install chromium
npm run test:browser   # with npm run dev already running
```

Unit tests cover immutable truth, a complete solve, unsupported accusations, NPC memory, evidence gating, contradiction/witness routes, connection validation, save recovery, and malicious remote responses. Browser smoke tests cover rendering, movement, notebook persistence, physical clue collection, interrogation, contradictions, interview memory, board connections, a complete written verdict, and mobile layout. Save fixtures place the player at test locations; world tests separately check the full aisle and clue accessibility. No external AI account is needed for tests.

The accusation evaluator is a conservative English key-fact heuristic, including negation checks; it is not a general natural-language proof system. Write short affirmative sentences distinguishing the act, death, motive, and evidence. The ending explains each assessment criterion.

## Standalone macOS application

Download a DMG from [GitHub Releases](https://github.com/Ninnja10563/The-Last-Train/releases). Choose **mac-arm64** for Apple Silicon (including M3). This release ships only the validated Apple Silicon application. Open the image, drag The Last Train into Applications, eject the image, and launch the installed application. No browser, Node.js, or running development server is required. All game assets, fonts, and audio work offline; only optional AI direction needs its configured service.

These community builds are ad-hoc signed, not Apple Developer ID signed or notarized. If macOS blocks the app, review its entry in System Settings → Privacy & Security and choose Open Anyway. Managed Macs may prohibit this. Future notarized releases require Apple Developer signing credentials; none are embedded in this project.

Application saves live in Electron's user-data directory (`~/Library/Application Support/The Last Train` on macOS). Browser saves remain separate: use Settings export/import to migrate a case.

To run the desktop application from source:

```sh
npm ci
npm run desktop
```

Build an Apple Silicon disk image on a Mac with `npm run package:mac`. Intel packaging is available with `npm run build && npx electron-builder --mac --x64 --publish never`, but it is not included in releases because the hosted Intel runner could not initialize WebGL for validation. The `.github/workflows/desktop-release.yml` workflow also builds the Apple Silicon application on a native macOS runner when a `v*` tag matching `package.json` is pushed. The workflow runs unit tests, verifies the app signature, tests the packaged application (rendering, sandbox, movement, export/import and restart persistence), verifies the DMG, and publishes the installer plus its SHA-256 checksum only after all checks pass.

The Electron renderer is sandboxed with Node integration disabled, a restricted `app://game` asset protocol, and a content security policy. The desktop wrapper does not open a local network server. Optional AI endpoints must allow CORS for `app://game`.
